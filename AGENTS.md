# Reference Rule

Before implementing knowledge base, document processing, chunking, embedding, retrieval, RAG, knowledge graph, model provider, or storage, inspect `D:\school\WeKnora-main` first when that development reference is available. Record the architectural idea and independently implement the 408-specific contract. If the reference is absent, use the recorded design notes; never add it as a prerequisite or fetch it during build/test/deployment. Do not copy its modules, routes, schema, prompts, or UI to create an apparent independent implementation by renaming symbols.

# Independent Implementation

408 Assistant owns its frontend, backend, database schema, API, knowledge base, knowledge graph, learning model, recommendation algorithm, Agent, and deployment definitions. General-purpose open-source dependencies are permitted; preserve their notices and distinguish them from project contributions.

Keep implemented capabilities separate from planned capabilities. Rule-based mastery is not a trained model; cited RAG is not an autonomous Agent; graph tables are not a working graph pipeline. Do not claim original algorithms or competition readiness without evidence.

Run `node scripts/check-independence.mjs` after changes to source, dependencies, assets, or deployment. This checks explicit reference coupling only, not code originality or visual similarity. Review those separately. Update `docs/independence.md` and `docs/WORK_PROGRESS.md` when capability boundaries change.
