# 公共教材、题库与个人资料的使用流程

## 资料组织

公共库由管理员维护；个人库归成员自己维护。一个文件只上传一次，在资料页选定学科、类型与用途。

| 类型 | 推荐用途 | 在问答中的角色 |
|---|---|---|
| 教材、课本 | 知识库；需要抽取课后题时选两者 | 首选定义、原理、条件 |
| 讲义、笔记 | 知识库 | 教材后的补充 |
| 真题、习题、模拟卷 | 题库 | 候选题，不把选项当结论 |
| 答案解析 | 两者 | 补充解题依据与关联答案 |
| 考纲 | 知识库 | 学习范围、目录；不作详细结论证据 |

自动分类是文件名/目录规则建议，不是内容识别或准确性认证。未能可靠识别时保留待分类，不能随意归为教材或真题。已有已确认分类保留。

资料页可按学科、类型筛选，选择文件后批量确认。仅维护者看到待确认资料；学生列表只展示已确认分类。`整理本库已有资料`复用已保存解析，仅对题库/两者用途生成待审核候选；不重传、不重新OCR。文件名没有学科信息的跨科文件可选综合。

旧导入清单中的类型可编辑；新导入脚本区分真题、习题、模拟卷，先按文件名再回退父目录规则。脚本不代表题目已审核发布。

## 题目、答案和解析

结构化题库与文档片段分开保存，以文件/页码/知识点关联。当前规则自动抽取编号单选题，支持括号编号、全角选项和跨页内容，不声称完整支持任意数学排版、证明题或图表恢复。解析异常、缺图、缺选项的候选不得自动发布。

管理员在题库与课程审核页核对题干、选项、答案和知识点。另一文件中的解析可在编辑题目时通过“关联另一文件的参考答案与解析”指定文件、页码、逐字原文；原文校验后仍为待审核。不能仅按相同题号跨书自动配对。原文存在不等于管理员已经核实解析与题目匹配。

问答末尾推荐最多3道同知识点、已发布且可用的题目，优先真题。没有合格题目时不伪造题目。相关推荐用于新回答，不回写旧聊天历史。

## 检索和回答

1. 识别题意、知识点；图片先转写，学生核对公式和条件。
2. 公共库选择只检索该库；个人库选择检索公共库加该个人库，绝不扩展到其他个人库。
3. 图谱路径和向量召回共同定位，先做相关性与证据过滤。按资料类型分组召回，减少大量习题挤掉教材的情况。
4. 达到相关性门槛的公共教材优先，其次个人教材、讲义和解析、笔记。类型优先不是事实正确性认证；选择题选项、目录和待分类资料不作为回答依据。
5. 模型生成带逐字证据的结构化解释或推导。后端核对引用原文和前提，再单独请求模型审查支持关系。审查不通过或格式不符则退回有界、完整的原文句子；没有充分证据时明确不足。
6. 正文直接回答，来源在末尾展示文件、页码、片段；计算推导明确标注，不能自动作为判分依据。

审查使用同一已配置模型，不是独立事实引擎，也不是形式化数学证明。不能保证小模型推导、教材OCR和资料本身没有错误。不接外部搜索补全事实。正常改写增加一次模型审查调用；本地模型仍可能较慢。

章节路径与精确条件保存在分块元数据中，不伪造摘要。最多保留4段、600字前提；超出预算或缺失上下文时标记不完整而不是默默删掉前提。新分块规则作用于后续处理；已有索引可按需用“升级本库分块与索引”，不必为批量分类和权限变更重跑OCR。

## 图谱与成员

图谱写入由后台同步，页面和问答不再同步替换整张图。页面显示同步提示和上次快照；Neo4j不可用或丢失快照时显示有标注的PostgreSQL来源图，并将缺失快照排队重建。默认最多160节点、48步布局，按学科/名称探索，手动展开最多600节点。源数据尚在同步期间，快照可能短暂滞后。

管理员资源页管理公共库；成员页显示个人库数量、原文件占用和配额，不显示个人内容。默认每人5个个人库，配额0至100，仅限制后续新建，降低配额不会删除已有资料。原文件占用是documents.size汇总，不包含历史版本、向量或数据库磁盘使用。

已有配置禁用个人库时，运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-kag.ps1 -EnablePersonal
```

该参数显式将PERSONAL_KB_ENABLED设为true；不修改模型密钥。升级自动执行迁移21，不清空数据卷，不删除教材，也不自动重新发布候选题。

排查图谱运行状态可执行 `powershell -ExecutionPolicy Bypass -File .\scripts\check-graph.ps1`。只检查容器、凭据是否可用及日志，不打印密码、不重设数据库密码、不删除数据卷。Neo4j图谱读查询逐层限制路径数量，不再修改命名空间计数器；关系展示按端点和类型合并，原始证据完整保留在PostgreSQL。网页页脚2026.10.31.2用于辨认此次前端，仍需重新构建容器并刷新页面。

## 2026-11-01 答疑界面与题目整理

答疑页保留全站顶栏，主区采用会话侧栏、消息流和底部输入框。来源与检索过程默认折叠，仍可查看图谱降级原因、原文页码和相关练习；手机通过侧栏按钮切换历史。图片须先识别并核对，再提交。网页版本与服务端版本不同会显示提示；start-kag.ps1还会检查运行中的API与前端HTML版本，不能只凭容器Started判定已更新。

管理员除不列出个人库外，按ID访问、修改、删除个人库或维护其文件也受到角色校验；曾经以普通成员身份建立的个人库仍保留，切回普通成员身份后按原所有权使用，不会因升为管理员而删除。

普通OCR完成提醒不再等同于解析失败，缺字、失败、低质量等警告仍阻止发布。章节答案区不会永久吞掉后续章节；仅在章节和题号均明确、答案唯一时关联。导读和没有选项的问答题不再被自动误建为单选题；完整解析开放题、复杂公式与多图仍需人工校对。题库审核将正常待审核与需修复候选分开显示，不删除既有记录或测评快照。对旧文件使用“整理本库已有资料”即可复用解析结果应用新规则，不必重新OCR。

教材召回可补查同一文档、相同章节附近两个块范围内的正文，帮助恢复被切开的问题动因。邻接段仍受知识库权限、当前版本和原文引用约束；这属于文档上下文召回，不冒充图谱检索成功。

## 分文件答案批量关联与目录关系（2026-11-01）

管理员资料页新增“题目与答案在不同文件？”：题目文件须已设为题库/两者用途并生成候选；选择同库的答案文件，核对书名、版本和试卷范围后预览。默认仅关联章节与题号均唯一的记录；章节命名不同可显式指定题目章节与答案章节，再更新预览。重复题号、冲突答案、阻断解析告警不自动配对。

确认关联后仍待审核，不覆盖已发布题目；每批最多200题，已关联且内容未变的不重复写入。预览指纹与文件/解析/题目版本校验防止覆盖并发修改。跨页解析分别保留每页来源，不把续页文字标为第一页。明确A–F答案可填入选项；只有文字解答时保留原文解析，仍待确认选项，不用AI猜测判分。当前不是所有题型、所有答案表格的通用解析器，未匹配项仍可逐题关联原文。

旧候选缺章节/题号时，配对接口复用题目解析补读元数据；不能识别的记录需先“整理本库已有资料”，不必重传或重新OCR。尚未关联答案不等于资料中没有答案。

图谱为已有知识点补入管理员目录中的上下级和已维护关系，标记canonical_directory且明确不提供教材推导证明；仅涉及本库已匹配点及其祖先，不凭空加入演示知识。迁移22排队重放图谱，目录维护会自动标记更新。概览按连通邻域取点，减少限量采样把连线另一端丢掉；真实孤立或无明确依据的节点仍可能存在。

“为什么”问答在已召回依据内平衡原有限制与缓解机制，保留原文前提；覆盖提示是规则检查，不是形式化语义验证，不能保证任意教材、OCR或模型回答绝对充分。当前部署版本2026.11.01.2。

本机批量关联命令（管理员在本机终端登录，密码不显示、不写入报告）：

```powershell
py -3 scripts/pair-answer-files.py --apply
```

仅对文件身份归一化后完全一致且两边均唯一的文件执行预览和关联；年份、版本、作者等标识保留，仅科目名称不视为同一本书。先复用已保存解析整理题目，每批重新预览获取指纹，再关联为待审核；不能唯一识别的文件写入`.cache/answer-pair/report.json`，需在网页指定文件/章节。该命令不会删除资料、自动发布题目或重新OCR。去掉`--apply`仅生成预览。

### 回答完整性与图谱覆盖（2026.11.01.3）

真实兼容接口模型通过独立JSON请求整理答案，并进行逐字证据定位、支持核验和完整句检查。提供商报告长度截断、半句结尾或核验失败时重试；仍失败则明确显示失败并保留来源，不将原文摘录标成成功整理。来源检索保持教材优先；无法据此保证OCR或模型事实零错误，真实本机Ollama效果须实际验收。

图谱分类综合全部已确认资料学科，规范目录优先；跨学科与缺少可靠学科依据分别展示。页面列出目录关系、文档定位关系、共现关联及孤立节点数，分类核对可跳转来源资料。孤立概念不等于已完成的语义图谱，不会为消除孤点而编造关系。

`powershell -ExecutionPolicy Bypass -File scripts/start-kag.ps1 -EnableGraphExtraction` 可显式启用后续文档处理的模型候选关系抽取（需已配置LLM；云接口可能计费）。这不会自动重处理全部旧资料；旧资料按需在资料管理重试/重建。当前抽取有输入长度上限，不等于全书每一页均已抽取；未获得原文支持的关系不会入库。迁移23只更新已有图谱的分类读模型，不能替代关系抽取。

### 资料清洗与旧索引升级（2026.11.01.4）

更新镜像后，旧图谱快照中的明确广告店名、题干片段和不可靠代码标签会在读取时被过滤，关联边随之退出当前图谱；来源与原文件不删除。后台按迁移24重放过滤后的Neo4j快照。同块共现只表示共同出现，不再用于问答路径扩展。

管理员在公共库资料管理点击“升级本库分块与索引”。新的分块指纹使旧索引失效，解析版本与文件未变时复用解析检查点，无须重新上传或重跑OCR。新修订清洗广告水印、空白和控制符，重新计算块偏移，再切块、索引和构图；完成前旧活动版本继续服务。缺少检查点或解析器版本改变时仍需重新解析。不要删除数据卷。

清洗不猜改“然厕”等汉字误识别，不改数学运算符；无法识别字符会提示核对，含替换字符的片段不作为回答证据。未知英文标签被保守过滤，规范目录不受此筛选影响。这不是对全部OCR错误的语义纠错。

正常回答使用模型整理加来源核验。模型超时/不可用时若有充分的完整原句，返回明确标为“教材完整原句”的降级结果及出处，不冒充模型生成；不足则说明依据不足。单次模型请求上限300秒，概念问答最多选3个主片段，核验只生成短JSON，用户可停止生成。页面显示核验进度和具体连接错误。真实本机模型仍需实际提问验收。

### 协议主题约束与Ollama诊断（2026.11.03.1）

问题明确写TCP/UDP/HDLC等协议时，宽泛的“传输层”“可靠传输”重合不能让其他协议的段落成为答案依据。图谱按问题协议定位并过滤、去重路径，扩展查询保留原协议。概念讲解保留直接点名协议的完整句和同段连续条件；显式比较问题保留双方。协议表与连续句规则有界，不是通用语义消歧器。TCP可靠传输问题至少须有序号、确认、重传机制依据；只有“TCP提供可靠服务”的定义会提示不足，不拿链路层讲解替代。

中文标点后的纯排版空白参与引用等价匹配，数字、字母、公式与实质文字仍严格核对。未获原文支持的事实不能由模型常识补齐。

用户日志仅有 `/healthz` 时，不能据此确定先前模型500的原因。`ollama ps`只列驻留模型，空表不代表未安装。管理员“服务连接检测”现测试与问答相同的JSON接口。Windows可在项目终端执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/check-ollama.ps1 -Model qwen2.5:3b
```

脚本连接本机11434，列已安装/驻留模型，分别发普通及JSON短请求；可能临时加载已安装模型。不会读取`.env`、下载模型、修改配置或发送用户资料。输出安全错误类别，不打印服务原始响应。若配置了其他模型，请修改`-Model`为实际完整名称。内存错误或模型进程失败须在Ollama服务端解决；代码更新不能替代此运行条件。已部署用户只需拉取重建，无须因主题筛选重新上传或重建全部索引。

### 宿主机正常、后端失败的诊断（2026.11.03.2）

宿主机短请求通过只证明该端点在当时能处理短输入，不能证明容器配置相同或真实问答可运行。新版模型客户端访问host.docker.internal、本地IP及已知内网服务时直接连接；公共服务仍遵守代理环境。不得把此风险修复描述为已经证明了具体500原因。

管理员答疑侧栏的“服务连接检测”从后端实际配置发请求，显示目标主机和模型名（不含URL凭据、查询参数、密钥）。图谱检测失败仍继续模型检测。短JSON通过后再测约两千字的合成输入，帮助区分配置差异、路由问题及长请求运行失败；云端可能计费，不发送用户资料。后端180秒检测预算，页面195秒等待，可查看逐项结果。正常使用Windows宿主机Ollama时，Docker后端目标通常是host.docker.internal:11434，模型名应与已安装完整名称一致。

模型整理证据预算按完整正文/前提组控制在约3200字符内，不截断条件；来源复核只传必要章节标签。明确TCP章节可支持同段未重复TCP名称的机制句；普通检索提示不能替代章节来源。保活与TIME_WAIT不再替代可靠数据传输的序号/确认/重传机制。图谱问答查询预算为8秒，超时仍明确降级，不伪称成功。

更新只需拉取、重建并确认2026.11.03.2，再在新对话测试。无需因本次访问路径修复重新上传教材或重建全部索引。仍失败时提供后端检测的各项结果，比重复宿主机短测试更有诊断意义。

### 事实编号生成契约（2026.11.03.3）

旧格式让模型同时改写正文、逐字抄写quote和维护文件编号；引文格式偏差会导致正确改写被拒绝。现由服务端从有权限的教材片段建立完整原句目录，只向模型提供事实id、文本、出处位置和所需前提。模型输出 `claims[].text/kind/facts`，事实id不等于文件号；文件id与页码由服务端映射，模型不能新造。正文可归纳改写，来源区域保留原文，不把模型改写当作原文。

生成优先使用JSON Schema强制编号字段，已知不兼容时依次降级JSON object与JSON提示模式。引用越界、缺乏原文、截断、未保留必要条件及语义审查否定仍拒绝。语义核验是模型判断，不是形式化证明。只有机制名称而无细节时，只能概括已有结论并说明所引用片段的范围，不能用模型记忆补全细节。

后端日志记录 `answer grounding rejected` / `answer validation failed` 的安全分类，不记录原文或模型完整响应。旧资料无需重新上传、重建索引或更换模型，更新代码并新建会话即可使用新契约。

可选本地真实模型测试：在已运行并安装qwen2.5:3b的本机设置 `OLLAMA_TEST_URL=http://127.0.0.1:11434/v1`，执行 `go test ./internal/service -run TestLocalOllamaFactAnswerEndToEnd -v`（backend目录）。测试仅使用合成教材，不读取用户资料。本次云端拉取模型因仓库Forbidden未完成，不能将合成响应回归称为真实Qwen质量通过。
