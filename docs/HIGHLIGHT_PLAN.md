## 用户流程

回答中点击有效引用编号或引用卡片 → 右侧打开资料阅读面板 → 显示标题、PDF物理页码、实际引用片段 → 跳到原页并高亮关联区域。手机以全屏阅读面板呈现，关闭后回到原对话。提供上一处/下一处与取消高亮；原文件仍可单独打开。

高亮表示检索片段在原页的位置，不证明模型解释一定正确，不把 AI 生成题的知识依据当作该题标准答案。第一版优先段落/内容块级定位，不承诺任意文档逐字高亮。

## 现状与缺口

- 当前 openDocument 获取本人文件 Blob 后交给浏览器默认阅读器，PDF 页码通过 #page 传入，无法可靠控制默认阅读器中的自定义高亮。
- 结构化解析已有页码、块 ID 与归一化坐标；RAG 引用已有文档、分块、片段和页码。
- 分块当前根据 page.Text 切分，没有持久化到原始内容块的可靠对应。不能仅因为同页有坐标就宣称能够精确高亮。

## 候选实现

1. 解析保存：统一块 ID、阅读顺序、原页坐标基准（尺寸、裁切与旋转等）。块坐标必须与显示的原页一致；OCR 图片坐标与 PDF 显示坐标须校验转换。
2. 分块映射：保存分块来源的块 ID、文本范围和解析/文档版本。对 page.Text 的拼接、空白归一化、重叠分块建立确定的范围映射，不使用全文关键词匹配猜坐标。完整引用块与展示截断片段需要区分。
3. 引用输出：后端从检索命中生成可信来源列表；模型只使用允许的编号。前端只将确实存在的来源编号变为交互入口；来源位置取后端记录，不接受模型捏造的页码/矩形。
4. 内置阅读器：PDF 候选为 Mozilla PDF.js，按页渲染并叠加透明高亮层；将归一化坐标转换为当前页面 CSS 尺寸，缩放、旋转、设备像素比变化时同步更新。按需加载，避免长教材所有页同时渲染。参考 [官方示例](https://mozilla.github.io/pdf.js/examples/)，选定版本与 API 在实施时核对。
5. 文件类型：文字 PDF 和扫描 PDF 先做块/区域高亮；扫描件使用 OCR 位置，保留原页。TXT/Markdown/DOCX 使用标明“解析文本”的阅读视图定位片段，不伪装成 Word 原排版，不伪造页码。
6. 权限与历史：文件和定位接口均校验本人权限；不在 URL 中传令牌。历史引用带版本，重处理后不盲目将旧坐标画在新内容上；旧定位不可用时保留历史片段并提示。原文已删除时明确告知。

## 范围与降级

- 精确的证据块映射可用：高亮对应内容块；文字层可靠时再增强到句子/文字。
- 仅有页码：跳页并展示引用片段，说明暂无精确定位。
- 存在多个重复片段或坐标质量不足：不随机选择位置。保留页/段落定位。
- 跨页引用：分别定位各页的证据区域，不画跨页大矩形。
- 首版建议包含 PDF 块级高亮、其他格式解析文本定位、真实引用编号交互、历史版本与定位失败提示；逐字高亮、全文搜索与完整编辑器作为后续增强，仍待用户确认。

回答 Markdown/表格/公式渲染属于任务 5 另一子项，可独立实现；它不提供原文位置，也不依赖视觉模型。高亮本身不需要调用大模型。

## 验收

- 引用点击后定位到合成文档预设的正确页和区域，重复词不导致错位。
- 缩放、旋转、高 DPI、手机布局下保持对齐，表格公式区域可框选。
- 扫描页、无位置旧资料、重处理、原文删除与越权访问各有明确行为。
- 历史会话恢复、多个引用切换与返回聊天正确；无映射时降级，不伪造高亮。
- 合成样本可先验收工程，真实教材高亮质量后续抽样验证；旧资料需要重新处理才能补齐新映射。
