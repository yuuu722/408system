# 公共知识库上传、图谱与多用户管理

更新：2026-10-19。对应数据库迁移 15。

## 从旧版升级（Docker Compose）

Windows 用户可以在项目根目录执行：

```powershell
git pull origin main
powershell -ExecutionPolicy Bypass -File .\scripts\upgrade-knowledge.ps1
```

脚本只更新下列非秘密配置，先在已忽略的 `.cache/config-backups` 中备份 `.env`，保留数据库、JWT、管理员令牌等配置，并重建 Docker 服务。首次管理员初始化仍须由部署者完成，不会自动提升普通账号。

也可以手动修改**现有 `.env`** 中的对应配置（不要覆盖已有数据库、JWT、管理员令牌或模型密钥）：

```dotenv
MAX_UPLOAD_MB=200
EMBEDDING_MODE=lexical
DOCUMENT_PARSER_MODE=builtin
PERSONAL_KB_ENABLED=false
AI_DEMO_MODE=false
GRAPH_EXTRACTION_ENABLED=false
DOCUMENT_JOB_TIMEOUT=2h
```

`.env.example` 不是运行时配置，更新模板不会自动修改已有 `.env`。设置 `lexical` 后无需任何向量模型或大模型 Key 即可处理资料；这不是语义嵌入或 AI 回答。若以后使用真实语义嵌入，设置 `EMBEDDING_MODE=remote` 并配置 `EMBEDDING_*`，重新处理文档。不同索引空间不会混用。

```powershell
git pull origin main
docker compose up -d --build
docker compose logs --tail 80 backend worker
```

后端镜像新增 Poppler 和 Tesseract（简体中文/英语），首次重建需下载系统包。数据库会自动升级到迁移 15，不需要删除数据卷。浏览器退出重新登录并刷新。已初始化的管理员账号保留；首次管理员初始化仍按 [公共课程说明](PUBLIC_KB_ADMIN_ROADMAP.md) 操作。

管理员进入独立工作台；普通用户进入学习概览。管理员在“公共资料管理”点击“重试本库所有失败任务”，恢复此前因缺少向量 Key 失败的内置讲义或其他文件，无需重新上传。

## 上传与解析

- 默认单文件 200 MiB，可通过 `MAX_UPLOAD_MB` 设置为 1–2048；前端从后端读取实际限制，Nginx 允许文件和 multipart 开销。后端对请求与实际复制字节同时限制，临时上传文件会清理。
- TXT/Markdown：支持 UTF-8、UTF-16 BOM 及可解码的 GB18030；编码转换保留提示。
- PDF：Docker 内置 Poppler 按页提取文字；正文不足时调用本地 Tesseract OCR。扫描页保留识别提示，空白/图片页不会伪造正文；整份资料无有效正文时给出明确失败。支持至多 2000 页。
- DOCX：内置提取正文和表格内文字；仅包含图片、复杂公式/版面需要另配结构化解析服务。内置处理不等于完整 Word/OCR/公式恢复。
- `DOCUMENT_PARSER_MODE=builtin` 不依赖旧模板中的宿主机 8091 地址；`remote` 显式使用独立服务及其令牌。独立 Python 服务须同步设置 `MAX_UPLOAD_MB`。
- 上传立即进入持久化队列，后台处理总时限默认 2 小时，可设 1 分钟至 4 小时。大量扫描页的耗时取决于 CPU；进度是处理阶段权重，不是耗时预测。

## 索引与图谱无需大模型

`EMBEDDING_MODE=auto` 在未提供向量 Key 时选择本地词法索引；`lexical` 强制使用中文字符二元组/词特征的哈希向量，计算并归一化后进入原 pgvector 索引。它是真实的本地词法向量，不是预训练语义模型；不调用 LLM，也不把演示向量冒充语义效果。已明确配置的远程服务失败时不会偷偷切换索引空间。

图谱先匹配管理员维护的规范目录。对“概念名：定义正文”形式的文本，再建立标为“规则定义候选”的概念节点，并将同一文本块中出现的规范知识点以 `related` 连接。该关系只表达共现，不代表因果、先修或经过人工确认的语义。规则提取不能覆盖任意自然语言教材，管理员可补充规范目录；可选 LLM 抽取保持原有证据校验与显式开关。

图谱页面提供按学科分列的节点连线图，支持搜索、缩放、点击邻接高亮和来源查看；单次最多绘制 600 个匹配节点，完整节点与关系列表仍可查看。

## 替换、删除和来源一致性

- “替换文件”保留文档 ID，新的文件和任务进入独立执行版本；旧 worker 的写入会被执行代号阻止。
- 新版本未就绪时，旧活动版本的检索、图谱和原文仍可用；成功激活后切换到新版本，清除旧分块关系和不再有证据的资料节点。
- 删除文件时，其分块、向量、派生关系和证据关联同步删除；目录节点不删除。
- 同一节点可由多个文件提供证据，删除其中一份仍保留节点并展示其他文件的来源。只有失去全部来源的非目录节点才会清理。
- 为历史引用保留版本文件记录；当前实现没有对历史源文件做磁盘垃圾回收，因此替换后旧文件可能继续占用上传卷空间。

## 管理员与普通用户

默认 `PERSONAL_KB_ENABLED=false`：普通用户只读公共知识库、课程与图谱，可继续测评及记录个人学情；不能上传、替换、删除资料或创建知识库。限制在后端执行，直接调用 API 也不能绕过。旧个人数据保留，仅从默认公共学习界面隐藏。

管理员有独立工作台和导航，可新建/修改公共知识库、上传/替换/删除文件、批量重试失败任务、新增/修改规范知识点、维护课程和试题。学习页与管理页分别展示。

“用户管理”支持用户名/邮箱搜索、每页 50 人的分页、授予/撤销管理员权限、停用/恢复账号。停用期间，已有登录令牌和新的登录请求均被后端拒绝；不能停用自己或撤销自己的管理身份，系统至少保留一位启用的真人管理员。列表不会返回密码散列。当前采用停用而非删除用户，以保留学习记录和公共资料归属；未提供任意读取学生个人对话或学情的入口。

## 验收

设置可创建隔离数据库的 `TEST_DATABASE_URL`，运行 `backend` 下 `go test -count=1 ./...` 和 `go vet ./...`；前端运行 `npm test` 与 `npm run build`。`TestPublicCurriculumEndToEnd` 覆盖公共只读权限、用户管理、超过旧 20 MiB 限制的上传、超限拒绝、失败任务批量恢复、无需模型的真实词法向量与规则图谱、重复证据、文件替换和删除后的图谱清理及原文版本切换。`TestIntegratedTextAndScannedPDF` 使用合成文字 PDF 和扫描 PDF 实际执行 Poppler/Tesseract；未安装这些工具的宿主机测试会明确跳过，Docker 镜像包含工具。测试不调用收费模型。


## 2026-10-20 公共资料与答疑

公共库默认不再提供内置示例讲义/练习，由管理员上传正式资料。升级迁移只清理未编辑的旧示例，保留四科目录及自行上传的资料；旧示例物理文件暂不回收，引用旧示例的历史对话可能无法再打开来源。

智能答疑严格检索下拉框所选知识库，不自动混入其他公共库；旧 IncludePersonal 参数不再扩展检索范围。上传必须处理完成，并使用与当前检索相同的向量空间。正常 AI 组织回答需要配置 LLM_BASE_URL、LLM_API_KEY、LLM_MODEL，并设置 AI_DEMO_MODE=false；lexical 索引无需嵌入模型密钥。模型未配置时不能生成 AI 回答。无依据不调用回答模型。引用显示文件、来源位置、原文摘要，点击编号查看原文。模型输出通过引用编号校验后才展示，校验失败展示原文摘录。该校验不保证语义完全忠实，请核对原文。


## Word 文档和失败任务恢复

更新 Docker 后支持 Word 97–2003 二进制 `.doc` 及 `.docx`。内置流程使用 LibreOffice Writer 排版转换，再按页提取文本，对文字不足的页调用中文/英文 OCR。保留原始 Word，转换缓存与资料一起存储。图片中的公式和复杂表格可能识别不准确；转换页码可能与 Word/WPS 排版不同，引用会标明“Word转换第 N 页”，阅读器展示对应页的解析文本、警告并可下载原文件。独立 Python 解析服务仍只接受 PDF/DOCX；DOC 由 Go 先转换后发送 PDF。

运行 `git pull --ff-only origin main` 和 `docker compose up -d --build --force-recreate backend worker frontend`。等待镜像构建完成后，对已有图片 DOCX 在管理员页面点击“重新处理”，无需重新上传。任务解析指纹已更新，旧失败的解析检查点不会被误当作新结果。运行原目录导入命令续接批次。该批次源目录及 classification.csv 不要改动；新加 DOC 文件应另建批次或重新规划导入。


## 交互知识图谱

四科分别使用蓝、绿、橙、红色；未能唯一归科的资料概念为灰色。节点大小由可见关联数量决定；相关知识围绕核心节点聚合，连线上显示中文关系标签。拖动节点调整位置，拖动画布空白处平移，滚轮或加减按钮缩放。支持学科筛选、节点搜索、只看选中节点和邻居、显示/隐藏名称及关系文字。搜索保留直接邻居，帮助理解上下文；匹配超出 600 节点时提示缩小范围。右侧展示完整名称、说明、节点与关系证据，点击来源打开原文件。规则共现不等于因果/先修关系。

这次仅更新展示，不重建后端图谱，不更改资料或证据。节点/关系数量取自实际知识库，不保证和参考图相同。实际数据不含某个关系时，前端不会为视觉效果编造连接。更新命令：`git pull --ff-only origin main`，然后 `docker compose up -d --build --no-deps frontend`；无需重新上传或重新 OCR，也不重启正在运行的 worker。


## 文字与图片智能答疑

选择知识库后输入文字，或添加 PNG/JPEG 题目图片（最多 10 MiB、1600 万像素）。图片通过单独的鉴权接口识别，先检查知识库访问权限。配置 VISION_BASE_URL、VISION_API_KEY、VISION_MODEL 时由视觉模型转写题干、选项和可见图示条件；否则调用 Docker 内置 Tesseract。视觉模型不是知识来源，识别阶段禁止解题。用户核对/编辑转写文字后再发送；本地 OCR 不能理解电路、拓扑等图形，应补充关系或配置视觉模型，公式均需核对。图片识别最多并发 2 个请求，多余请求返回繁忙；有效处理临时文件自动删除，原始问题图片不加入知识库、不保存到历史，历史保存用户核对后的文字。

文字处理按透明规则识别问题类型，匹配规范概念辅助检索；后续仍严格使用所选知识库。会话显示“理解问题 / 检索依据 / 组织回答”阶段和检索概念，这些不是知识证据。只有检索到的文档片段可以成为答案依据；回答显示引用编号、原文件名称、页码/片段位置和原文摘录，点击可查看原文。无足够依据不调用回答模型；无效引用编号回退到原文摘录。编号校验不代表每句语义已获形式化证明，仍需复核。

回答模型仍需配置 LLM_BASE_URL、LLM_API_KEY、LLM_MODEL，设置 AI_DEMO_MODE=false。本地 lexical 检索不再错误地要求嵌入模型密钥；remote 模式仍需有效嵌入服务。缺少回答模型时页面显示原因，不冒充 AI 答案。显式 demo 模式不调用外部图片模型。视觉模型及回答模型分别调用其服务商，按各自配置计费。

更新：`git pull --ff-only origin main` 后执行 `docker compose up -d --build backend worker frontend`。无需重新上传知识库文件；现有索引和图谱保留。


引用阅读器与原文件打开操作同时传递文档版本号，避免历史回答的旧片段被错误地配到新版本原文件上。历史版本若已清理则明确显示不可访问，不替换成当前版本来冒充来源。


本地 lexical 索引先取较大的向量候选集，再按问题有效关键词覆盖率排序和筛选，不把长片段稀释后的余弦分数直接当成语义置信度；该分数是词面匹配分数而非语义证明。同义改写但没有词面重合时仍可能拒答。远程嵌入保留向量门槛，检索范围仍受所选知识库权限约束。


## 答疑不可用的分层检查

发送按钮灰色表示后端配置检查未通过，尚未开始检索。页面现在分别指出缺少 `LLM_API_KEY`（回答模型）还是 remote 模式缺少 `EMBEDDING_API_KEY`。lexical 不要求嵌入密钥，但 AI 措辞仍需要服务商有效回答密钥及匹配的 LLM_BASE_URL、LLM_MODEL；不能使用示例文字当作密钥。修改本机 .env 后须重新创建容器读取配置。不要向他人公开密钥。

管理员可在智能答疑页点击“检测问答连接”，最多等待约 45 秒，分别显示检索服务和回答模型错误。它调用实际接口，可能产生模型调用费用；仅发送合成检测文本，不读取或发送知识库资料，也不回显模型原始回答和密钥。学生账号不能触发该检测。检测成功只表示接口响应有效，不保证索引空间一致、问题可在库中找到或模型答案正确。

502 是代理/后端连通问题，与回答模型的缺配置不同。新版 Nginx 每 5 秒刷新 Docker DNS，在后端 IP 更换后可恢复；启动期间仍可能短暂失败。Compose 后端 `/exam408 healthcheck` 检查通过后才启动前端，不再依靠手动重启前端解决旧地址缓存。

更新：`git pull --ff-only origin main`；`docker compose up -d --build backend worker frontend`。现有数据库、资料、索引、图谱保留。如需确认密钥是否进入容器，只打印配置是否存在，不打印密钥本身：

```powershell
docker compose exec -T backend sh -c 'echo LLM_API_KEY_CONFIGURED=${LLM_API_KEY:+yes}; echo EMBEDDING_MODE=$EMBEDDING_MODE'
```

`LLM_API_KEY_CONFIGURED=` 为空代表当前容器没有有效的非空环境值；`yes` 仅表示非空，仍需通过连接检测确认服务商是否接受。
