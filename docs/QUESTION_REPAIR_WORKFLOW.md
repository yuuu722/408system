# 概念反转防护与题库修复（2026.11.06.3）

## 这次解决的代码问题

- “多次性却必须一次性全部装入”“虚拟存储器的驻留性特征允许换出”等已知概念反转增加拒绝检查，允许“不需要一次性装入”“打破传统驻留性”等正确否定表达；事实目录和摘录回退也不使用这些已识别的错误句。提示词强调核对肯定否定和特征归属。这是少量高风险断言的防护，不是所有教材知识的正确性证明，真实小模型仍需本机验收。
- 编号单选题支持题号与正文分行、全角数字、数字和标点间空格、字母选项单独成行或以空格分隔、括号答案标签；仍不从缺失选项中编造选择题。显式多个答案不能偷偷取第一个当单选答案。
- 问题图片按结构化文本偏移关联，避免每道题都附上同页全部图片。存在可定位OCR置信度块时，只阻断重叠题目行；未知/结构性页面失败仍阻断整页。答案文件相同地按可定位行检查，原文引用保留全角原貌，仅题号标识规范化。
- 复用现有解析的“整理”操作保护已发布、人工编辑及已有关联答案证据的题目：即使新抽题结果为零，也不删除或覆盖这些成果。此保护针对当前活动解析的重新抽题，不等于更换源文件时永远保留陈旧题目。

## 本机使题目进入练习的顺序

1. 拉取并启动2026.11.06.3，先不运行全库重新OCR。
2. 管理员进入公共资料管理，核对题目文件用途为“题库”或“两者”。只有“知识库”用途不会抽题，这是有意分离教材证据与题库。
3. 点击“整理本库已有资料”，复用已存解析。展开“逐文件抽题结果”，看哪些被用途跳过、哪些确实识别为零，而不是把文档就绪当成题库已发布。
4. 题目和答案在不同文件时，先在资料页预览同版本、章节的答案配对；无唯一匹配时指定文件与章节，不能只按重复题号猜配。
5. 进入“题库与课程审核”：计数区区分候选题、已可练习、待审核、待修复与缺答案。修复题干/选项/图片、选择正确知识点，核对原文答案。只有无解析问题且具备可靠答案与知识点的题目能勾选。
6. 勾选已逐题核对的候选，点击“发布选中且已核对的题目”，确认后逐项执行现有带版本检查的保存接口。失败单独显示，不伪报全部成功。学生只看到已可用公共题目，提交有效作答后才形成学情。

不直接在数据库把status统一改成ready，不自动发布模型猜测的答案，不插入演示题掩盖题库为空。缺图、主观/多选题或文字本身缺失的资料仍需修复；本轮单选抽取改进不等于已实现所有题型自动判分。若保存的原始解析已经丢了内容，只整理不能恢复，需对相应文件重新处理而不是反复全库重跑。

新代码不会在云端自动修改你电脑中的资料或发布题目；以上操作需在实际部署执行。源码更新和数据处理结果是两回事。

## 2026.11.07.1：本机已上传资料批处理

无需重传资料，无需先执行全库重新解析。在项目目录拉取、重建服务后运行：

```powershell
git pull --ff-only origin main
powershell -ExecutionPolicy Bypass -File scripts/start-kag.ps1
py -3 scripts/complete-question-library.py --apply
```

输入本机管理员账号和密码。省略 `--apply` 仅生成计划和当前候选题缺项报告；配对预览是只读POST。功能标识检查要求后端支持新完整性保护，旧镜像不会继续写入。

工具处理系统公共库（也可 `--kb-id` 指定其他公共库）：

- 识别明确的习题/真题/模拟卷及题库用途文件；答案专用文件不单独抽成题目。教材保持知识库用途。题目资料原为 knowledge 时改成 both，保留其问答检索用途和已有学科/审核分类。
- 顺序复用已存解析抽候选题，不上传文件、不触发OCR或模型生成，不修改已保护的人工成果；非ready文件跳过并记录。
- 独立题目与答案仅自动关联唯一同书名/年份/版本身份。每200题事务前重新预览校验指纹。保留已有可靠答案+实质解析，可靠答案冲突不覆盖；已发布题目不覆盖。题号/章节有歧义不猜配。
- 输出 `.cache/question-batch/report.json`（逐文件、配对进度及错误）、`documents.csv`（文件ID、未抽出题目的文件）、`questions.csv`（逐题缺项）。进度JSON原子写入，可重跑。CSV防止文件名被表格当公式执行。报告不保存密码、题干、题图或答案原文。
- 结构检查包含题干、选项、资料答案、实质解析、知识点、来源说明、解析异常及需核对题图。**字段齐备不等于答案语义正确，不等于已人工审核。** 有多少原始题未被识别无法仅从候选表得知，因此零候选文件另列，不能以候选数量宣称原书全部题已成功。

自动身份无法识别时，查看 `documents.csv` 的ID，在生成的 `pairs-template.csv` 中填写题目文件ID、答案文件ID；章节名应与网页配对预览返回的章节一致。另存 `pairs.csv` 后运行：

```powershell
py -3 scripts/complete-question-library.py --pairs ".cache/question-batch/pairs.csv" --apply
```

同一题目文件/章节不可映射多个答案文件。明确配对表优先于该文件的自动配对。工具校验两个文件都属于所选公共库，仍须人工确认版本。解析缺字/公式丢失、主观题/多选题、原书没有解析、配对歧义不能靠批处理凭空补齐；按报告修复对应文件或逐题补充可靠来源。当前不承诺所有题型自动判分，也不自动发布候选题。完整候选须在审核页核对后发布才能进入学生练习。

接口 `GET /knowledge-bases/{id}/question-inventory` 仅管理员可用，公共库范围过滤；SQL去除题图字节与Evidence引文，只返回用于本机完整性检查的题目字段。客户端报告只保留元数据与缺项，不泄露私人知识库。

Windows报告占用修复：Excel/WPS等可能锁定已打开的CSV，使替换报告报WinError 5。工具现在对JSON和两份CSV统一采用独立临时文件原子替换；目标不可替换时另存 `*-latest-随机标识.*`，在终端显示真实最新路径，后续检查点复用该备用文件。原先被占用的文件保持不变，不能用它查看最新进度。若目录不可写则明确报错，关闭文件或指定 `--report-dir ".cache/question-batch-new"` 后可重跑；已完成的数据处理不回滚，也不需要重新上传。

## 2026.11.07.2：自动修复和校验发布，不再逐题确认

用户已授权自动处理公共题库。在更新并启动新服务后运行：

```powershell
py -3 scripts/complete-question-library.py --apply --auto-publish
```

此模式会自动扫描题目用途文件及教材中的编号单选题。教材用途改为 both，资源类型仍为教材，保留教材问答检索。原答案专用文件不独立当题册抽题，但会被用于答案关联。

新增处理：

- 题干必须非空且具有连续完整的A、B等选项；普通正文中的字母变量、只有一个选项或缺题干的片段不再作为新单选候选。已有未编辑、未引用、未发布的旧抽取结果按现有整理规则被新结果替换；人工/已发布/外部答案证据保留。
- 教材同文件后部的答案解析按章节+题号唯一回配，支持带括号答案、显式题号/答案双行表格；答案表与单独标记的详细解析只有各一条、章节题号一致且不冲突时合并，保留两处原文证据。重复/低置信度/答案冲突不猜配。
- 单独文件名或题号不一致时，补充按完整题干及所有选项顺序精确匹配答案文件；必须存在明确单选答案、带标签且有实质内容的解析，且只找到一份匹配。仅知识点相同、仅题号相同、只有答案字母不能靠此规则配对。名称中含答案/解析/解答/详解或类型为solution的资料参与补配。
- 未关联知识点可从原文解析中寻找唯一最强术语匹配；有并列候选则保留未关联，不把学科目录随意当作知识点。
- 新管理员公共库接口 `POST /documents/{id}/resolve-answers` 补配，`POST /documents/{id}/publish-verified` 校验后每批发布最多200题。发布端重新从当前保存的解析重建题干选项，验证显式来源答案与实质解析、章节/题号或完整内容唯一匹配、知识点、OCR异常及题图。客户端不能传ready或答案绕过验证。事务锁定来源文档、解析及目录并检查版本/指纹，题目乐观版本比较防止覆盖并发编辑。无需操作者逐道勾选。
- 进度报告增加逐文件Published、Summary.Available和AutoPublished，配对歧义/发布拦截原因保存为元数据。CSV被占用仍自动另存；可安全重跑，已发布题不重复发布。

这是有原文依据的自动处理，不承诺自动修复所有原文丢字/缺图、公式OCR错误、主观题/多选题或原书未提供的解析；也不使用模型猜测来凑齐答案。未修复记录自动保留报告，不能冒充学生可用题。没有原文证据的解释不会自动生成后当成教材原文。云端仍未访问用户本机资料，9672条实际修复与可用数以本机新版执行结果为准。原先省略 `--auto-publish` 的命令仍只整理候选，不发布。

按章节/题号配对的自动发布还会在服务端检查同书名/年份/版本身份，不能仅凭客户端曾关联过答案就发布；不同文件身份须满足完整题干和全部选项内容匹配。因此人工曾误配的不同书名答案不会被自动批准。对于纯答案表而没有题干的、书名也不能唯一对应的文件，保留未修复，不拿相同题号冒充相同题目。

## 2026.11.07.3：根据实际报告修复漏处理并导出保存文本诊断

实际报告6384条候选中3904条所属文件没有进入自动处理阶段，包含ResourceType=other的教材、solution类型的真题解析合订本；其中还包含94条大纲历史候选，不能都当真实试题。跨文件完整内容补配新增数量为0，数量报告本身不能证明是哪些原文格式/OCR问题。

自动模式现在对所有非考试大纲的已上传保存解析执行 `AutoDetect`，不再由猜测的资源类型决定是否抽题。服务端先识别，只有发现实际编号单选题时才把知识库用途增加为both；未发现题目的知识资料保持原用途，已保存的分类/学科/审核状态保留。已发布题目仍受保护。大纲历史候选不再计入有效题库范围，在报告ExcludedNonQuestionRecords单独保留，不删除源资料。

命令保持 `py -3 scripts/complete-question-library.py --apply --auto-publish`。额外自动生成 `.cache/question-batch/diagnostics.json`：每份资料统计新抽题数、答案条目数、具体警告/阻断原因，并保存最多4页、每页最多6000字符的现有解析文本样本（选项页、答案页、警告页/中部格式页）；还包括最多5条截断的答案解析条目。只导出本次公共库的少量保存文本，不导出图片、密码、个人库或完整教材，不触发OCR或模型。若报告目标被占用，最新路径仍以终端打印为准。

普通questions.csv新增ExtractionIssue原始阻断说明；旧“存在解析异常”泛称改为“存在阻断原因（见ExtractionIssue）”，因为Issue还包含知识点未匹配等业务原因，不能据此统计OCR损坏率。该修复确认解决文件覆盖遗漏；尚未读取用户真实保存文本样本，不能宣称所有剩余6356条已经修好。零抽题/答案格式问题后续应依据自动诊断原文定位，而非再盲目重跑全库OCR。

若只需导出样本，可运行 `py -3 scripts/complete-question-library.py --diagnostics-only`。该模式只有本机登录和GET读取，不整理、配对、发布或修改队列，也不覆盖原report.json；仍需使用支持诊断接口的新服务。正常自动模式会在修复结束后自动导出，无需再单独执行。
