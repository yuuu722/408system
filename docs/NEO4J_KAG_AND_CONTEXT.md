# Neo4j、KAG 与个人知识库升级（2026-10-30）

## Windows 启动与旧数据升级

保留已有 `.env`、PostgreSQL 数据卷和 uploads 数据卷。在项目 PowerShell 终端运行：

```powershell
git pull --ff-only origin main
powershell -ExecutionPolicy Bypass -File .\scripts\start-kag.ps1
```

脚本仅在缺失/空值或 JWT 为模板占位值时生成本地密钥，保留现有模型配置；不输出密钥。缺少 `.env` 时从模板建立。首次需要拉取 Neo4j Community 镜像，等待所有服务启动后打开 http://localhost:5173。

Compose 启用 Neo4j 和 KAG，并显式设置 `PERSONAL_KB_ENABLED=true`，所以旧 `.env` 中关闭个人库的值不影响 Compose 的新权限功能。Neo4j 使用独立随机密码和持久化 `neo4j-data` 卷；只向宿主机回环地址开放 7474/7687。不要提交真实 `.env`，也不要通过 `down -v` 清空已有卷。Neo4j 初始化后的密码不随修改 `.env` 自动重置，需要按 Neo4j 自身流程修改。

已有图谱自动从经过校验的 PostgreSQL 构建记录同步到 Neo4j，不清空历史文档/学习数据。图谱页面显示实际存储后端。用户打开图谱或问答时检查同步代号；后台也会重试未同步任务。

已有文档不会因为拉取源码自动改写向量。在资料管理选择知识库，点击“升级本库分块与索引”。旧活动版本在新版本完成前继续可用；解析版本与文件未变时复用保存的页级解析检查点，仅重新切块和索引。没有可用检查点或解析配置改变时仍可能重新解析。请观察处理进度，不要重复上传。

## 数据职责与一致性

- PostgreSQL：账号、权限、文件元数据、解析页、原文块、pgvector 向量、学习记录、经过校验的图谱构建/来源记录以及同步日志。
- Neo4j：实际用于图谱浏览和一至两跳关系遍历的属性图读模型，节点和关系按知识库命名空间隔离。不是仅换一个页面标签。
- 上传卷：原始资料及已有预览缓存。

PostgreSQL 仍保留图谱构建记录作为可恢复来源，不宣称已经删除所有 PostgreSQL 图谱表。图谱更新在 PostgreSQL 事务中标记同步日志，随后用单个 Neo4j 事务替换该知识库快照；失败不标记同步成功，后台重试。知识库删除使用墓碑清理 Neo4j 命名空间。图谱版本标记缺失时可从构建记录重建；切换时不丢弃旧来源。

2026-10-31 可用性修复：Neo4j 连接/同步失败不再使资料与审核服务退出。图谱页明确标记“已保存图谱（恢复模式）”并展示带权限校验的构建快照，后台继续重试；这不是 Neo4j 查询成功。问答图检索不可用时明确标记 `rag-degraded`，只使用所选库文档证据，不冒充已执行图推理。删除原文或旧块后，图谱定位到的块还会在 PostgreSQL 中重新校验存在性、文档用途、知识库与用户权限。

## 当前 KAG 问答链路

```text
问题/核对后的图片文字
  → 规则规划原问题、显式子句和匹配知识点（有界查询）
  → 在选中知识库的 Neo4j 图中定位实体，最多两跳路径检索
  → 使用路径实体扩展检索词，检索文档向量并合并图谱定位原文
  → 过滤无效片段，补入可追溯的前提原文
  → 模型选择完整原句编号，由服务端组装教材原句
  → 原文匹配、前提依赖及回答长度校验
  → 正文 + 回答下方来源 + 可折叠 KAG 检索路径
```

KAG 在本项目中包含向量文档检索这一 RAG 环节，但 KAG 一词没有统一的严格包含定义。当前是自主实现的、有界图谱与文档证据组合链路，不依赖或声称实现某个第三方 KAG 框架的全部功能；规则规划不是自主 Agent，图谱两跳不是通用符号证明系统。目录或 `related` 关系只用于导航，不能被当作因果证据。没有图谱匹配时明确说明仅使用文档证据，不编造推理路径。Neo4j 不可用时本次回答明确降级为文档检索，图谱权限错误仍直接拒绝。

当前回答显示检索路径；历史会话保留回答和引用，不额外持久化完整图遍历过程。模型输出保持原句组织策略，不能以模型记忆补齐新结论。仍需配置可用的回答模型；Ollama 等本地模型无需付费 API。

## 分块与前提

- 页内以句末/段落作为优先边界，单块最多约 900 个 Unicode 字符，尽可能保持约 120 字重叠；章节变换不重叠串接。
- 连续章/节标题合并，保存书名、检测到的章/节路径、页码、版本、文本位置和原有坐标。
- 前提原文与正文分开保存；从局部前文及必要的上一页补充有界片段，最多两段。每段保留原始页、段和偏移，不使用模型编造“背景摘要”。
- 选择依赖前提的正文时，必须同时保留关联条件原句，或正文选句本身已经包含完整条件；缺失会触发校验失败。回答限制最多 8 段、总长约 1600 字，避免无界拼接。
- 明显续接词却没有补充上下文时保守跳过。识别不出的章节、复杂跨章指代、长公式和 OCR 错误仍有局限；不能保证所有教材的隐含前提被自动恢复，也不保证原文事实正确。复杂情况应核对原文或补充问题条件。

## 个人知识库

普通用户可建立、改名和删除自己的知识库；可上传、替换、删除、关联、整理分类及重建自己资料的索引。选择知识库后，问答和图谱只在该知识库范围内工作。不会隐式把私人资料加入公共问答。

公共库仍只有管理员可维护；学生不能通过请求体指定 `IsPublic=true` 创建公共库，也不能读写其他用户的私有库。Neo4j 图查询使用知识库命名空间，实体/关系不是只靠前端隐藏来隔离。

## 验证与边界

代码回归包含真实 PostgreSQL 隔离库、专用 Neo4j 5.26 Community 容器、多跳路径、两个命名空间同节点 ID、私有访问拒绝、参数化查询、图谱丢失重建、异常脱敏和删除清理；包含章节/前提来源偏移、依赖缺失拒绝与浏览器个人库上传/图谱/KAG 路径流程。没有用真实收费模型验证教学准确率。

Go 集成测试须显式设置 `TEST_DATABASE_URL`。真实图谱测试另外设置 `NEO4J_TEST_URL` 和 `NEO4J_TEST_PASSWORD`，只能连接专用测试实例，不能指向生产 Neo4j；测试创建随机隔离 PostgreSQL 数据库和随机知识库命名空间。未设置时相关测试跳过。

Neo4j Community 是独立通用容器依赖，使用上游镜像并保留其许可证；项目通过 HTTP 事务接口访问，不复制其实现。


## 2026-10-31 页面与回答回归修复

迁移19只标记已有活动图谱重新同步一次，以应用旧来源外键兼容读取，不删除来源、向量、题目或学习记录。
