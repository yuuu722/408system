## 2. 技术架构

### 后端

- Go HTTP API，入口为 `backend/cmd/api/main.go`。
- 使用 `net/http` 路由和中间件。
- PostgreSQL 作为权威业务数据库。
- pgvector 保存 1536 维文档向量并执行相似度检索。

- OpenAI-compatible LLM 和 Embedding 接口。

- TDesign 仅按页面需要加载 Drawer、Dialog、消息组件等能力。
- 页面使用异步路由拆包，主入口构建产物约 189 KB，原实现约 1.49 MB。

### 部署

`compose.yaml` 包含：

- `postgres`：PostgreSQL 16 + pgvector。
- `redis`：Redis 7。
- `backend`：Go API。
- `frontend`：Nginx 托管的 Vue 生产构建。
- `postgres-data`、`redis-data`、`uploads` 三个持久化卷。

## 3. 已实现功能

### 3.1 用户与权限

- 用户注册、登录、当前用户查询和前端退出。
- bcrypt 密码哈希。
- JWT HS256 身份认证和过期时间。
- 用户知识库、文档、对话、学习状态和推荐数据隔离。
- `JWT_SECRET` 必填，少于 32 字符或仍为示例占位值时拒绝启动。
- API 内部错误不会直接暴露给前端，每个请求带 `X-Request-ID` 便于查日志。

### 3.2 知识库和文档

- 创建、查看和删除个人知识库。
- 上传、查看、删除和重新处理文档。
- 支持 TXT、Markdown、文本型 PDF。
- 文件类型、扩展名、大小和文件名安全检查。
- 文档状态：`uploaded`、`processing`、`ready`、`failed`。
- 重新处理时立即进入 `processing`，旧分块不会在处理期间继续被检索。
- 文档处理设置 10 分钟超时并记录失败原因。

暂不支持扫描型 PDF OCR、DOCX、表格结构恢复和复杂版面解析。

### 3.3 文档处理和检索

- 默认分块约 900 个 Unicode 字符，重叠 120 个字符。
- 批量生成 Embedding。
- Embedding 数量与分块数量不一致时任务失败，不写入不完整结果。
- `ReplaceChunks` 使用数据库事务替换同一文档的全部分块。
- HNSW + cosine pgvector 索引。
- 检索同时校验用户、知识库和 `documents.status = 'ready'`。

### 3.4 RAG 问答

- 选择个人知识库提问。
- 问题向量化并检索 Top K 分块。
- 使用相似度阈值过滤低相关证据。
- 返回答案、对话 ID、引用片段和识别到的知识点。
- 引用包含文档 ID、标题、分块 ID、位置、摘要和相关度。
- 保存用户消息和助手消息。
- RAG 辅助事件失败会写日志，不再静默吞错。
- 无足够证据时，回退模式会明确提示资料不足。

未配置真实 LLM/Embedding Key 时，当前能力只适合演示流程，不能作为真实语义检索质量证明。

### 3.5 408 业务层

- 初始化数据结构、计算机组成原理、操作系统、计算机网络四科。
- 初始化 11 个第一阶段演示知识点和 3 条前置关系。
- 文档可以手动关联到知识点。
- 根据知识点名称和关键词识别提问涉及的知识点。
- 学习状态包含掌握度、薄弱度、置信度、交互次数和最近交互时间。
